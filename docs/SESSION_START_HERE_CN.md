# 新对话必读：项目上下文

## 项目边界
- 本仓库 `nereis-lullaby` 只负责《蜜忒之歌》文字冒险 / 视觉小说游戏。
- 《Nereis-Hero》是独立的动作探索 RPG，另有仓库和开发流程。不要在本仓库开发 RPG 内容或代码。
- 两款游戏共享世界观，但不要求重复同一段剧情；必须避免互相矛盾的事实、时间线、角色认知和事件结果。
- 当前仓库是重新开始的设计基线；旧代码不再作为架构或玩法约束。

## 最高优先级创作规则
1. **草案不是定稿。** 助手提出的例子、候选剧情、结局可能性都必须标注为提案，不能自动升级为 canon。
2. **不要擅自决定结局。** 包括 Hero 最终命运、复国军是否腐化、蜜忒的最终命运、跨游戏结局因果链。
3. 用户提出意见时，内部比较正反方案后给出有结论的建议；不需要输出内部辩论过程。
4. 关键叙事决策先写成“提案 / 待确认”，得到用户明确认可后才更新“已确认设定”。
5. 文档中英双语维护；不要触发 GitHub Actions。
6. 以实际工具结果为准，不得声称未做过的仓库操作、运行测试或游戏内验证。

## 已确认的方向
- 以蜜忒视角展开。她是外神的代理人，但她自己并不知情；她的纯真和情感应当是真实的，不应简单解释为伪装或操控。
- 这款游戏需要比短篇纯文字视觉小说更丰富的玩法；探索、生活活动、人物自主行为和线索推理都是候选核心。
- 玩家应看到蜜忒和村民主动生活、行动，而不只是站在地点等玩家点击的静态 NPC。
- 蜜忒遇见 Hero 前后，日常行为都可能在客观上参与某种仪式；蜜忒未必理解这些行为的意义。这是核心设计方向，具体仪式规则仍待设计。
- 村庄生活中的行动、村民之间的关系和关键事件共同推动剧情。
- 角色关系与世界调查 / 结局条件是相关但独立的维度。不能把身体结合或某个亲密事件当作主要结局的硬门槛。

## 尚未定稿
- 邪教仪式中心究竟位于村庄内部、森林深处，还是两者构成复合结构。
- 仪式的真实目的、机制、时间线和谁知道多少。
- Hero 到来后各人物的具体行为、任何跨游戏衔接情节。
- “凡人之墓”“永恒乐园”“烈火天罚”的最终内容与判定条件。
- 村民最终成为一百名邪教徒并保护蜜忒，是一个有潜力的候选构想，不是定稿事件，也不限定属于哪个结局。

## 开发原则
先建立可玩的核心循环和小型垂直切片，再扩展完整剧情、角色数量和地图。新对话先读本文件及其他四份双语设计文档。
