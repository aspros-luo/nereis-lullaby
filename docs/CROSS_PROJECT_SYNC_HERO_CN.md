# 跨项目同步记录：Nereis-Hero 地图与共享世界观

> 日期：2026-10-12  
> 状态：同步备忘；不新增世界观定稿  
> 适用项目：Nereis Lullaby / 蜜忒之歌

## 1. 同步原则

- Nereis-Hero 与 Nereis Lullaby 是玩法和视角独立的两个项目，共享已经确认的世界事实。
- Hero 仓库里的地图、战斗、临时道具和调试场景属于实现内容，不会自动成为 Lullaby 的剧情 canon。
- 只有用户明确认可的世界观事实才可从“提案 / 待解决”升级为“已确认”。
- 中英文设计文档需要同步；不得触发 GitHub Actions。

## 2. 当前共享的已确认方向

- 蜜忒的纯真与情感是真实的；她不以普通人类的自觉理解自己与外神的关系。
- 教会研究、古神遗留力量、王国信仰体系与外神影响是相关但不同的力量层次。
- 村民拥有各自的生活、关系和动机；参与异常不代表每个人都理解仪式。
- 两个游戏允许视角和信息量不同。玩家知道的内容不自动等于蜜忒或 Hero 知道。
- 共享世界观不要求两款游戏重复同一段剧情，但人物认知、时间线和事件因果不能互相矛盾。

## 3. Hero 当前地图实现：仅作开发事实记录

Hero 的 development 分支正在复核 A0–A12 主区域与 H01–H08 正式隐藏区域的箱庭连通性，重点包括：

- A2–A4 的森林高路、废弃城区、下水道 / 水库与回环；
- A5–A8 的战场、修道院、监牢和王墓空间层级；
- A9–A12 的王城外环、大圣堂、研究深层与内城；
- 隐藏区域的灵视条件、入口显现、回程和状态持久化。

这些是关卡空间与实现信息，不应被解释为 Lullaby 必须发生的剧情地点或事件。具体环境线索只有在后续剧情设计明确批准后，才成为跨项目共享叙事事实。

## 4. 明确保持为提案 / 待解决的内容

- 仪式中心位于村庄内部、森林深处或两者构成复合结构。
- 村民是否会集体成为邪教徒并保护蜜忒；若会发生，其时间点、动机与结局归属。
- Hero 与蜜忒的最终命运，以及两个游戏之间是否存在明确的因果衔接。
- 复国军是否腐化、H09 临时候选区域及其遗物的剧情意义。
- “凡人之墓”“永恒乐园”“烈火天罚”的最终条件和跨游戏因果链。

Hero 仓库中存在的 H09 候选洞窟与候选遗物已被标记为非正式地图内容，并与结局资格解耦。Lullaby 不应把它当成既定世界事实。

## 5. 后续同步流程

每当任一项目增加关键剧情、道具、角色认知或时间线事实时：

1. 先检查它属于已确认事实、提案还是待解决问题。
2. 检查另一个项目是否会因此出现人物认知、时间线或因果冲突。
3. 只同步必要的共享事实；不把一个项目的玩法规则强加给另一个项目。
4. 更新中文与英文文档。
5. 对尚未获得用户认可的内容，保留提案状态，不写成定稿。

## 6. 本记录的边界

本文件只是跨项目同步备忘，不批准任何新结局、仪式机制或角色命运，也不替代两款游戏各自的设计合同。


## 7. 需要持续跟踪的跨项目设计张力

Lullaby 的 `DESIGN_CONTRACTS_CN.md` 明确要求：关系与调查是不同维度，身体结合或某个亲密事件不应成为主要结局的硬门槛。Hero 当前实现则将 `physical_union_complete` 用作 H08 深层出口的门槛之一。两者首先是各自游戏的玩法合同，不应机械复制；但若未来把这次事件定义为跨游戏共享的同一历史事件，必须重新检查因果与角色认知，不能让 Lullaby 的主要结局被 Hero 的单一事件反向锁定。该差异现标记为“需持续跟踪”，不是擅自修改任一项目的既定设计。
