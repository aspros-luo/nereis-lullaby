> 方法：先定信息架构与义务分歧，再定可玩旗帜；**暂不锁死数值阈值**。

## 0. 专业人士会先做什么（我们正在做的）

1. **结局情感身份**写死（已有）  
2. **玩家在终局前必须能感到的差异**（不是说明书差异）  
3. **信息三层**：蜜忒相信 / 玩家可推断 / 世界事实  
4. **义务线索链**：每条结局至少一条「若错过则不成立或不可理解」的链  
5. **可观察分歧点**：选择改变世界与关系，而非改旁白道德评分  
6. 最后才是：旗帜名、阈值、UI——样板阶段只预留旗帜名

## 1. 两条结局的终局体验（设计验收）

### 永恒乐园

- 玩家应感到：爱与日常被推到「再也分不开」。  
- 蜜忒仍可以是纯真的；可怕的是**结构成全了在一起**。  
- 不宜读成：她从开头就在骗你。  

### 烈火天罚

- 玩家应感到：必须打断某种「温暖的继续」。  
- 打断里仍有爱（不忍、余温、灰）。  
- 不宜读成：单纯觉醒打反派胜利。  

### 共同

- 都不是标准 HE。  
- 都依赖玩家**做过的日常与锚点**，不是最后一题问答。

## 2. 条件维度（不用单一进度条）

用 **多维旗帜/参与**，终局根据组合落点，而不是一条「乐园值」。

| 维度 | 含义 | 乐园倾向 | 天罚倾向 |
|------|------|----------|----------|
| **A. 日常结合度** | 烹饪、赠食、照料互动、把日子过实 | 高：爱被养厚 | 高也可→更痛的打断 |
| **B. 仪式参与度** | 丰收节帮忙/献食、公开层配合 | 高：结构吃进日常 | 低或中 + 看清 |
| **C. 裂缝认知（玩家层）** | 重读、林缘、口径不一、节后物/人变化 | 低～中：仍沉浸 | 高：无法再假装只是过节 |
| **D. 拒绝/打断** | 是否在关键处停止配合、追问、离开结构 | 低 | 高 |
| **E. 蜜忒关系质感** | 是否仍珍惜她（非数值恋爱条） | 需要「真的在乎」 | 同样需要，否则天罚变虐菜 |

原则：

- **乐园**：高 A + 高 B + 偏低 C + 低 D（走进去且不撕开）  
- **天罚**：高 C + 高 D，且 A 或 E 足够（爱过/在乎过才有资格「结束」）  
- **E 不足**：不走向完整结局，而应导向「未完成/早终」或逼回日常（后定）  

数值阈值：**未定**。先保证每个维度有**可玩来源**。

## 3. 线索架构（按锚点，非按百科）

线索服务「重读」与维度 C，不服务说明书。

### 链 1 — 家与保护之爱（钉心 + 外皮）

| 阶段 | 玩家见到 | 层 |
|------|----------|----|
| 早 | 老婆婆叮嘱吃饭、摆花瓶、给草药 | 蜜忒：被爱 |
| 中 | 同一种叮嘱在节后语气变浅/变稳 | 玩家：不安 |
| 晚 | 保护与名单/节庆的并置 | 世界：结构 |

### 链 2 — 口与手（烹饪/赠食）

| 阶段 | 玩家见到 | 层 |
|------|----------|----|
| 早 | 做饭、送出、被感谢 | 爱的动手 |
| 中 | 节庆长桌、献食 | 个人爱 → 集体仪式 |
| 晚 | 食物/甜味在异常后的重读 | 乐园燃料或天罚不忍 |

### 链 3 — 丰收节公开层

| 阶段 | 玩家见到 | 层 |
|------|----------|----|
| 节中 | 热闹、名单、过满秩序 | 蜜忒：过节 |
| 节后 | 花瓣、空位、人的疲与柔 | 玩家：过满 |
| 再后 | 与林缘/降临的隐线勾连 | 世界：双仪式之一 |

### 链 4 — 裂缝与林缘（天罚主粮）

| 阶段 | 玩家见到 | 层 |
|------|----------|----|
| 早 | 习俗两种说法、商人随口 | 可忽略 |
| 中 | 林中「还不知道采什么」→ 知后仍不安 | 可选深挖 |
| 晚 | 不可问的问题、缺席、声音 | 高 C |

### 链 5 — 救人插曲（中段，后置内容）

- 当时是善。  
- 重读时可能加重乐园（羁绊）或天罚（必须保护/结束某种未来）。  
- **不在本阶段做透。**

## 4. 可玩旗帜预留（无阈值）

```
# 参与
flag_festival_done
flag_festival_helped
flag_festival_offered_food
flag_cooked_count_band          # 低/中/高 段，非精确分
flag_gifted_to_caregiver

# 认知（玩家层，由观察/对话解锁）
flag_seen_festival_aftertaste
flag_seen_dual_custom_conflict
flag_seen_forest_edge_unease
flag_knowledge_moonleaf

# 拒绝/打断（后置）
flag_refused_festival_role
flag_pressed_forbidden_question
flag_broke_routine_once

# 钉心（软）
flag_mite_bonded_daily          # 多次有温度的日常互动累计段
```

终局判定：**组合逻辑**，例如（示意，非定稿）：

- 乐园候选：bonded + festival 参与深 + 裂缝认知未到高 + 无强打断  
- 天罚候选：bonded + 裂缝认知高 + 至少一次强打断/追问  

具体布尔式待试玩后再写进代码。

## 6. 建议推进顺序（专业节奏）

1. **确认本文**情感身份与四条主链（本文）  
2. **放慢日常**：进节前增加可读文字事件（仍少系统）  
3. **节后暗线补「物」**：1 个可观察物件  
4. **林缘一条可重读观察**（抬 C）  
5. 再写终局组合布尔与两段收束文案  
6. 救人与降临完整版后置
