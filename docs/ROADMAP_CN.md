# 开发路线图

## 阶段 0：干净设计基线
- [x] 明确本仓库只负责文字冒险游戏。
- [x] 写入中英双语世界观、设计约束、玩法提案和新对话入口。
- [ ] 完成旧分支清理与新分支策略（需确认 GitHub 连接器可执行的分支删除能力）。

## 阶段 1：核心循环原型
- 建立最小可运行的文字冒险项目，不沿用旧项目代码。
- 实现时间 / 行动机会、地点切换、活动选择和事件调度。
- 实现 3 名村民的日程、关系和自主事件。
- 实现线索簿及可追溯的事件记录。
- 实现森林探索与一个阶段异变事件。

## 阶段 2：垂直切片
- 完成约一周游戏内时间的可玩内容。
- 异变前后复用场景但改变文本、人物行动与环境线索。
- 验证关系、调查和世界阶段之间没有隐式硬门槛。
- 进行引擎运行和人工游玩测试，记录问题。

## 阶段 3：叙事设计
- 确认村庄与森林、教会、古神遗留力量的关系。
- 确认关键人物的知识边界、时间线和事件因果。
- 在系统可验证后再设计完整路线和结局。
- 所有结局名称和构想在确认前保持提案状态。

## 阶段 4：内容扩展
- 扩大地图、村民数量、个人剧情、集体活动和异变阶段。
- 添加音乐、美术、演出和文本表现。
- 通过回归测试检查事件顺序、漏看线索和结局可达性。

## 工程纪律
- 先验证核心玩法，再扩大内容规模。
- 不以旧项目代码为必须保留的基础。
- 不触发 GitHub Actions。
- 每次汇报说明已完成内容、验证方式、未完成项和下一步。
