# 序章垂直切片实施计划（方向 B · 均衡推进）

> 状态：已批准的开发执行计划；具体场景对白与异变细节仍属于原型内容，不自动成为正式世界观。
> 版本基线：`development` 分支。Godot 实机验证和人工游玩由项目维护者在本地执行；开发提交不代表测试已通过。

## 目标交付

交付一段可从头开始、可中途保存并恢复、可正常结束的 Galgame 式序章。核心体验应形成完整闭环：

**日常建立 → 人物关系 → 细节矛盾 → 第七日异变 → 旧地点回访 → 克制的序章收束。**

保留当前七个地点、七日三时段、三名关键 NPC、线索簿、事件台账、信息网络与单槽存档。优先演进现有代码，不为抽象而抽象，不提前扩大为全村动态模拟。

## 实施顺序与预计工作量

| 编号 | 工作包 | 具体工作 | 验收标准 | 预计开发量 |
|---|---|---|---|---|
| P0 | 核心回归与边界修复 | 复核时间推进、行动消耗、NPC 在场校验、异变触发、结束条件、存档跨系统一致性；修复静态审查能确定的问题 | 核心冒烟测试与日程边界测试覆盖关键边界；失败操作不得留下半套状态；没有未经检查就宣称通过的测试 | 1–3 天 |
| P1 | 七日叙事连贯性 | 明确每日的情绪/信息作用；减少重复对白；为人物个人片段、已发现线索和异变回访建立呼应；所有隐藏解释保持提案状态 | 首次游玩可理解当前生活目标；关键证据至少有一条替代发现路径；对白不把推测写成事实；蜜忒仍不知道自己的隐藏身份 | 3–6 天 |
| P2 | NPC 行动与可观察后果 | 连接确定性自主行动、人物记忆、关系反馈和玩家在场观察；只传播角色有合理渠道得知的信息 | 同一时段 NPC 不会出现在多个地点；玩家不在场时不直接看见其行动；关键状态变化有事件来源；存读档后结果一致 | 2–5 天 |
| P3 | 序章收束与体验整理 | 完善异变后的地点反馈、结束文本、重新开始、目标提示、线索簿可读性与保存/读取反馈 | 玩家可结束序章并明确看到收束；完成状态能保存和恢复；重新开始重置全部运行时子系统；错误操作有清楚反馈 | 2–4 天 |
| P4 | 文档与交付 | 同步中英文路线图、验收清单、试玩说明和版本变更记录 | 中英文文档内容一致；明确区分已实现、静态检查、自动化执行、引擎验证和人工验收 | 与 P0–P3 并行，约 1 天 |

以上为粗略开发日，不是日历承诺；任务之间会交叉进行。初步总量约 **7–14 个开发日**，视代码审查中发现的问题而调整。Godot 本地验证时间由维护者另行安排，不计入助手代码开发量。

## 验收门槛

### A. 核心系统
- [ ] 从第 1 天正常推进到第 7 天傍晚，异变只发生一次。
- [ ] 普通时段每次最多消耗一项主要行动；移动和观察不消耗。
- [ ] 不在当前地点的 NPC 不可交谈；非法日程与时间坐标安全失败。
- [ ] 事件、线索、关系、行动历史和信息传播保持一致；失败操作不发布临时状态。
- [ ] 损坏或跨系统不一致的存档被拒绝，当前运行状态不被部分覆盖。
- [ ] 保存 → 退出 → 重启 → 读取后，时间、地点、关系、线索、世界阶段、事件台账和信息网络一致。

### B. Galgame 序章体验
- [ ] 第一次启动能看懂基本操作、当前时段和可选目标。
- [ ] 三名关键 NPC 的对白与日常行为有差异，个人片段可被触发且不会重复奖励。
- [ ] 早期细节能在后续场景产生意义变化，但不会自动给出隐藏真相。
- [ ] 玩家错过一条重要对话后，仍有合理路径找到理解核心矛盾所需的证据。
- [ ] 第七日异变至少改变三个既有地点的可观察内容。
- [ ] 异变后回访三个不同地点即可结束序章；重复地点不计数。
- [ ] 序章收束呼应玩家实际经历，不把关系数值直接当成结局判定，也不把提案剧情定稿。

### C. 交付透明度
- [ ] 每轮提交说明变更文件、提交记录、静态检查范围、未执行测试和剩余工作量。
- [ ] Godot 测试由维护者本地执行；报告中不把“写了测试”说成“测试通过”。
- [ ] 不主动触发 GitHub Actions。
- [ ] 中英文文档同步维护。

## 暂缓事项

- 正式立绘、背景、动画、配音、音乐与音效制作。
- 扩充大量普通村民或构建全村级高复杂度模拟。
- 正式结局、仪式机制、隐藏身份揭露和跨游戏剧情条件定稿。
- 为现阶段尚未验证的玩法引入大型框架或新的外部依赖。

1. 本轮已提交内容与 commit 链接。
2. 解决的问题和可观察的玩家体验变化。
3. 验证等级：静态审查 / 测试代码已写 / 自动化测试已执行 / Godot 引擎验证 / 人工游玩。
4. 剩余工作量与下一轮任务。
