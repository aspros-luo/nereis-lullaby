# 核心玩法验收清单（开发用）

> 当前状态：代码原型已具备主要循环；Godot 引擎运行与人工游玩尚未完成。本文是验收门槛，不代表已通过。

## 开发顺序
1. 核心玩法闭环与存档回归
2. 人物矩阵接入实际决策与可观察后果
3. 剧情、支线、结局与演出扩充

## 第一阶段：必须验证的闭环
- [ ] 从第 1 天推进到第 7 天傍晚，阶段只切换一次。
- [ ] 普通时段只能消耗一次主要行动；换地点和观察不消耗主要行动。
- [ ] NPC 在日程表指定的地点出现，离开该地点后不应仍能交谈。
- [ ] 日常活动、交谈、个人片段会正确消耗行动，并产生预期的关系/线索变化。
- [ ] 重复观察同一线索不会生成重复条目。
- [ ] 第 7 日异变触发后，时间停止推进；地点观察、回访、对话与结束条件均可完成。结束前必须回访至少三个不同的有效地点；重复地点不计数，未到场或未知 NPC 不可交谈。
- [ ] 保存退出后重启，再读取：时间、地点、关系、阶段、行动记录、个人片段标记、线索簿、事件台账和信息网络保持一致；旧版 v1 存档升级后也要验证。
- [ ] 无效存档不会部分覆盖当前运行状态；线索簿条目与调查记录中的已发现事实 ID 必须一致，且每条线索都有事件台账来源；损坏的 NPC 标记、不匹配的行动历史、超前于游戏时间的信息网络与不满足回访条件的完成存档必须被拒绝。
- [ ] 事件 ID 去重；事实必须由实际事件支持；角色知识必须有明确来源；收到消息不自动变成客观知识。
- [ ] 普通观察与第七日异变的线索均有事件来源；未成功提交的对话不得提前修改线索或关系。
- [ ] 完整跑一遍核心流程，并记录阻塞、软锁、误导性反馈和可错过内容。

## 当前代码基线
- 已实现：7 个地点、7 天 × 3 时段、3 名关键 NPC、行动经济、日程、关系数值、线索簿、阶段异变、异变后调查、单槽存档。
- 已实现：事件台账、显式知识授予、延迟信息传播、初版确定性 NPC 日常选择。
- 新增保护：事件台账读取存档时检查必要事件字段、事实与首发事件一致性，以及事件引用的事实是否存在；线索簿也会先完整校验再原子恢复，拒绝重复或缺字段条目。
- 核心状态读取还会拒绝无效地点、重复/未知异变回访、缺失异变标记、重复线索 ID 与损坏的行动历史；序章完成必须满足三个不同地点的回访条件。
- 信息网络读取会校验收件箱与已送达消息的一致性、信念的消息依据及可信度范围；主流程还会检查消息引用的事实/来源事件/送达事件是否存在于恢复后的事件台账，并拒绝信息网络时钟超前于恢复后的游戏时钟。
- 尚未验收：Godot 4.6.1 实际运行、完整 UI 人工游玩、退出重启后的真实文件存档恢复。
- 工具限制：若当前环境没有 Godot 可执行文件，静态代码审阅不能替代引擎测试；不得把未运行的测试脚本报告为通过。

## 第二阶段的进入条件
只有第一阶段的引擎测试、存档回归与人工游玩问题都已处理，才扩大人物矩阵的运行时范围。人物矩阵可以继续维护为设计资料，但不要提前把所有候选人物、关系或因果线写成正式剧情。
