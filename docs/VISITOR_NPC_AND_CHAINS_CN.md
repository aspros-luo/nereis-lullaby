# 逗留 NPC、外界线索与连环事件

> 状态：工作稿 v1（2026-11-05）  
> 来源：与 Hero 线路对齐——会有 NPC 在村庄**逗留一段时间**，带来外界消息、线索、进度；可触发连环事件。  
> 依附：结局判定 v2 · 日常环技术框架 · 跨作结局映射。

---

## 1. 定位

| 类型 | 是谁 | 在 Lullaby 里干什么 |
|------|------|---------------------|
| **常驻** | 老婆婆、铁匠、村民… | 钉心、村内织入 V、日常爱的外皮 |
| **逗留（Visitor）** | Hero 线会路过/暂住村的角色 | **外界消息、线索、进度、连环事件**；有限期在场 |
| **短客商** | 商人等 | 弱版 visitor：交换 + 一两条线索 |

逗留 NPC **不是**第二个 Hero 通道，也 **不单独决定结局**。  
他们主要改：

- **C 裂缝认知**（外头的话、不一致的口径）  
- **线索/知识**（采集、地名、人物关系、Hero 侧进度的生活化投影）  
- **连环事件链**（来了 → 请托 → 后果 → 再来或留下痕迹）  
- 少量 **A/V**（若玩家招待、赠食、帮忙）  
- 可选触及 **F**（若其线索强化与 Hero 的联系，仍受 F_CAP 限制）

---

## 2. 与结局维度的关系

| 维度 | 逗留 NPC 如何影响 |
|------|-------------------|
| C | 主出口：外界消息、与村内说法冲突 |
| A/V | 招待、送礼、共同短事件 |
| D | 拒绝请托、中断连环、把人送走 |
| E | 仅当互动有温度且关乎蜜忒日常时弱加 |
| F | 仅当事件明确服务 Hero 通道时弱加；**禁止**访客线单独拉满乐园 |
| B | 若访客参与节庆或带来节庆外法 |

访客线拉高 C 时，会抬 **天罚** 倾向；若玩家只收消息却更抱紧村子与仪式，仍可走乐园——由整盘天平决定。

## 3. Visitor 数据（设计）

```text
VisitorDef:
  id
  origin          # hero_cast | merchant | other
  display_name
  stay_segments   # 逗留多少段日常（或到某旗帜）
  appear_when     # 日常段、旗帜、随机权重、连环前置
  location_id     # 多在 COMMONS / PATH / CLINIC
  knowledge_ids[] # 可聊出的线索
  trade_ids[]     # 可选
  chain_id        # 所属连环事件，可空
  love_skin_note  # 情/欲/利外皮（叙事备注）
```

在场规则：

- 仅在 `appear_when` 满足且 `stay` 未耗尽时出现在 `LocationPresence`。  
- 离开后可留 **痕迹**（观察文案、物品、某人语气变）。  
- 与 Hero 的「某章有谁在村」可同构，但不要求玩家通关 Hero。

## 4. 连环事件（Chain）

### 结构

```text
ChainDef:
  id
  steps[]:
    step_id
    requires[]      # 上一阶完成、访客在场、物品、维度门槛（慎用）
    visitor_id?     # 本阶主脸
    player_actions  # 听、帮、拒、赠、带路…
    effects:
      knowledge+
      dims Δ        # 以 C/V/D 为主
      flags+
      spawn_next?   # 下一步或另一 visitor
      leave_trace?  # 离村后观察
```

### 原则

1. **一条链 2～4 步**，不要做成第二个主线网。  
2. 可 **错过** 或只完成一半；漏步 = 不同痕迹，不是坏档。  
3. 拒绝是合法玩法（+D、可能少 C 或不同 C）。  
4. 链的结局影响只通过 **维度与旗帜**，不 `if chain_done: ending=...`。  
5. 文字优先：每步要有可读内容，配一个轻交互即可。

### 示例链（占位，非定稿剧情）

| 步 | 内容向 | 维度 |
|----|--------|------|
| 1 | 外人暂住公共场，说路上见闻 | C+ |
| 2 | 请蜜忒带话/送物给村内某人 | V+ 或 C+ |
| 3 | 说法与老婆婆/铁匠口径冲突 | C+ |
| 4 | 人离开；桌上多一件外地物件 | 观察痕迹，C 弱+ |

## 5. 外界消息的种类

| 种类 | 作用 | 注意 |
|------|------|------|
| 路况/远方政治 | 世界活着；可与凡人之墓侧远景兼容 | 不抢蜜忒主音 |
| 古神/异象传闻 | 抬 C；与 Hero 探索同构 | 蜜忒层可当闲话 |
| 关于「被救者」的消息 | 弱连 F | 不剧透 Hero 全剧情 |
| 采集/物产线索 | 知识门闩 | 已有商人样板可归入 |
| 请托与人情 | V 或连环 | 爱的外皮：利/情 |

## 6. 与现有系统衔接

| 系统 | 衔接 |
|------|------|
| IngredientKnowledge | visitor 对话 `learn()` |
| NpcIntentScheduler | 逗留期间可主动搭话/赠小物 |
| LocationPresence | 按 segment 上下架 visitor |
| WorldFlags | `visitor_x_left`, `chain_y_step2` |
| 结局 Resolver | 只吃维度；访客不进单独公式项 |

---

## 7. 实施顺序建议

1. Visitor 在场 + 离开痕迹（一个样板 NPC）  
2. 一条 3 步连环（听→请托→口径冲突）  
3. 再挂第二条或 Hero 相关弱消息  
4. 调 C/V 增量，避免访客线变成必刷天罚  

---

## 8. 一句话

**逗留 NPC = 定时的外界管道与连环故事；改线索与 C/V/D，不定结局开关。**  
村内常驻定日子，过路人搅动缝与进度，Hero 仍只是通道之一。
