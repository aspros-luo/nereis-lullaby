# 结局判定逻辑（设计稿）

> 状态：工作稿 v1（2026-11-05）  
> 结局：永恒乐园 / 烈火天罚  
> 原则：多维倾向，非 bool 网；数字可调，结构先稳。

---

## 1. 输入：六个维度（0～100）

实现可用 `int` 0～100；对玩家不可见。

| ID | 名 | 主要来源 |
|----|----|----------|
| A | 日常结合 | 烹饪、赠食（非 Hero）、照料互动、有效日常段 |
| B | 仪式参与 | 丰收节帮忙/献食/配合公开层 |
| C | 裂缝认知 | 节后观察、林缘、口径冲突、重读事件 |
| D | 拒止打断 | 拒绝角色、追问禁忌、中止配合、破坏常规 |
| E | 钉心 | 与蜜忒相关的有温度互动累计（含日常与关键） |
| F | Hero通道 | 救人后：赠食次数、护符/贴身物、持续联系 |

事件 bool 只负责 **加减这些分**，不直接写 `ending =`。

---

## 2. 合格门槛（软门）

完整结局需要：

```text
E >= E_MIN          （默认建议 35）
且 max(A,B,C,D,F) 有过有效游玩 （非全 0 开局瞬结束）
```

不满足 → `ending = incomplete`（未完成/早终文案，后写），**不**强行乐园或天罚。

---

## 3. 两个权重（核心公式）

### 3.1 永恒乐园权重

强调：走进日常与仪式、通道深、少撕破。

```text
P = 0.25*A + 0.25*B + 0.30*F + 0.20*E
    - 0.20*C - 0.25*D
```

- C、D 高会明显压乐园（看清并拒绝时不应滑进乐园）。  
- F 权略高：跨作「心甘情愿/沉沦」与赠物链对齐。

### 3.2 烈火天罚权重

强调：看清、打断；仍爱过（E/A 垫底，避免冷血空烧）。

```text
T = 0.30*C + 0.30*D + 0.15*E + 0.10*A
    - 0.15*B - 0.20*F
```

- B、F 高会拉低天罚（深参与仪式+深通道时更难「烧断」）。  
- 若需「爱越深天罚越痛」：可把 A 的正权略增，不改变结构。

### 3.3 归一（可选）

若 P/T 可能为负：

```text
P' = max(0, P)
T' = max(0, T)
```

比较时用 P'、T'。

---

## 4. 落点规则

```text
diff = P' - T'

if E < E_MIN:
    → incomplete

elif abs(diff) < TIE_BAND:          # 默认建议 8
    → 进入「晚段决断」节点（见 §5）
    决断选择直接给出 paradise / blaze
    （可选：仍写入维度再算一次）

elif diff > 0:
    → paradise（永恒乐园）

else:
    → blaze（烈火天罚）
```

| 常量 | 建议初值 | 含义 |
|------|----------|------|
| E_MIN | 35 | 钉心不足不进完整结局 |
| TIE_BAND | 8 | 太近不靠小数点，靠最后选择 |

**禁止**用单个 `flag_xxx == true` 覆盖 P/T，除非是 §5 决断节点的一次性选择。

---

## 5. 晚段决断（天平太近时）

当 `abs(P'-T') < TIE_BAND`，不随机，不看隐藏小数，而给 **一次有字的选择**，例如：

| 选项倾向 | 示例方向（文案后写） |
|----------|----------------------|
| → 乐园 | 继续维持平常 / 再送出一件贴身物 / 不追问名单 |
| → 天罚 | 追问 / 拒绝再参与 / 中止给 Hero 的物 |

选择结果：

- **直接**定结局，或  
- `P/T` 做一次大额修正（如 ±25）再比一次——推荐 **直接定**，玩家更清晰。

## 7. 伪代码

```text
function resolve_ending(dims, tie_choice=null) -> Ending:
    A,B,C,D,E,F = dims

    if E < E_MIN:
        return INCOMPLETE

    P = 0.25*A + 0.25*B + 0.30*F + 0.20*E - 0.20*C - 0.25*D
    T = 0.30*C + 0.30*D + 0.15*E + 0.10*A - 0.15*B - 0.20*F
    P = max(0, P)
    T = max(0, T)

    if abs(P - T) < TIE_BAND:
        if tie_choice == PARADISE: return PARADISE
        if tie_choice == BLAZE:    return BLAZE
        return NEEDS_TIE_BREAK   # UI 进入决断节点

    if P > T: return PARADISE
    return BLAZE
```

## 8. 与 Hero 的对齐（逻辑层）

| Lullaby 落点 | 世界倾向 | Hero 侧易读成 |
|--------------|----------|----------------|
| 乐园（高 F、高 B、低 D） | 通道与结构都深 | 难完全抵抗、易心甘情愿 |
| 天罚（高 C/D、F 收敛） | 可打断、通道窄 | 较易抵制、可走焚断 |

不在此函数内读取 Hero 存档；只保证旗帜/维度语义兼容。

---

## 9. 调参与测试

最少测试剧本：

1. **深赠物 + 深节庆 + 少追问** → 应乐园  
2. **有钉心 + 多裂缝 + 拒绝/中止通道** → 应天罚  
3. **几乎不互动** → incomplete  
4. **两边都深** → 进决断节点，不看随机数  

调参只动：系数、E_MIN、TIE_BAND、增量表——不动「比较两个权重」的结构。

---

## 10. 一句话

**先累积六个分，再算两个权重，近则玩家决断一次；没有单独的 bool 结局开关。**
