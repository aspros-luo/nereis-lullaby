# 双视角世界线与因果事件合同（设计提案）

> 状态：架构提案，尚非正式世界观定稿。本文约束《Nereis-Lullaby》如何表达对共享世界的间接影响；《Nereis-Hero》的实际结局条件必须在其仓库独立实现并验证。

## 1. 核心设计

《Nereis-Hero》与《Nereis-Lullaby》不是两份互不相关的故事，而是同一世界因果链的两种玩家视角：

- **Hero：直接选择者。** 玩家通过探索、调查、战斗、结盟和明确抉择，决定英雄如何回应已经出现的机会与危险。
- **Lullaby：间接塑形者。** 玩家通过蜜忒的日常、关系、行动和对异常的接近/回避，改变信息何时出现、谁能接触谁、某些调查是否被引发，以及关键机会是否被保留。
- **世界：不围绕玩家暂停。** NPC 有自己的目标、日程、知识边界和压力反应。玩家可以影响他们，但不应把每个人变成等待玩家点击的剧情按钮。

这不是“蜜忒主动操纵一切”。玩家知道自己在选择行动，但蜜忒本人仍可以把这些行动理解为普通生活、关心或好奇；她的认知边界不能被隐藏系统打破。

## 2. 因果链，而不是结局开关

建议把剧情推进拆成可追溯的链：

`玩家行动 → 现场变化 → 角色观察/获知 → 角色判断 → 角色行动 → 后续机会变化 → Hero 可做出的选择`

每个箭头都需要合理的因果依据。不要用一个隐藏好感值直接决定结局，也不要让一个不相关的日常行动凭空改变世界。

例如，玩家在森林反复采花不应直接设置“永恒乐园=true”。它最多可以改变森林留下的可观察痕迹、村民的日常判断、Hero 是否注意到异常，以及后续调查是否有合理动机。Hero 是否深入调查、是否找到证据、如何回应，仍属于《Hero》视角的行动和判断。

## 3. 跨游戏事件合同

两款游戏之间应共享稳定的**世界事实/事件语义**，而不是互相依赖对方的场景节点、脚本路径或 UI 文本。

每个重要事件建议具备：

- `event_id`：稳定、不可随意改名的标识。
- `source_game`：事件来自哪个视角。
- `actor` / `target`：行动者与影响对象。
- `preconditions`：发生前必须满足的条件。
- `world_facts_added`：世界中确实发生了什么。
- `knowledge_grants`：谁因此知道什么、通过什么渠道知道。
- `opportunities_opened/closed`：新增或失去哪些后续机会。
- `evidence`：玩家可观察的现场、物件、对白或缺席。
- `recovery_path`：关键事实错过后是否仍有替代痕迹。
- `provenance`：这是已确认事实、原型内容还是未定提案。

必须分离三个层次：

1. **事实**：世界里实际发生了什么。
2. **知识**：每个角色知道、相信、误解或不知道什么。
3. **机会**：角色现在有条件做什么；机会不等于角色必然采取行动。

《Lullaby》可以输出稳定的世界线信号或事件摘要；《Hero》读取这些信号后，仍需结合 Hero 自己的行动状态决定调查、结盟和结局。当前不要求两款游戏实现运行时联网或共享存档。

## 4. 非定稿示例：复国军消息与森林调查

以下仅用于验证设计思路，不是已确认剧情或结局条件。

### 路径 A：消息进入 Hero 的生活

1. 蜜忒在与 Hero 的关系剧情中遇到外来者，因而听到关于复国军的消息。
2. 玩家决定是否把这件事告诉 Hero。
3. 若 Hero 获得可信消息，他可以尝试接触复国军；但消息本身不等于加入复国军，也不自动决定结局。
4. 在《Hero》中，玩家仍要完成相应接触、任务和选择。若这些行动成立，世界线才向“反抗教会/复国军相关”的方向发展。

### 路径 B：日常痕迹引发森林调查

1. 蜜忒多次前往森林，可能留下重复出现的采摘痕迹或触发某些异样。
2. 这些痕迹只有被其他角色观察、听闻或合理推断后，才会影响其判断。
3. Hero 可能因此调查森林。玩家在《Lullaby》中出于担心而回避、劝阻或改变相关互动，可能使调查动机减弱、时机推迟，或让某条证据链不完整。
4. Hero 是否深入调查，以及最终是否获得某件关键物品，必须由《Hero》的探索、条件与可恢复的证据路径决定。
5. “第三根脐带”在此是用户举例中的关键物品；《Hero》现有故事基线已将多部件隐藏遗物与 Hero 保持自主性、走向“烈火天罚”联系起来。尚未定稿的是它在两款游戏中的具体获取条件、森林调查的实际作用，以及错过它是否会让某条路线更难或不可达。不能把这些未定细节直接写成玩法硬条件。

这两条路径说明：Lullaby 影响的是**信息、动机、接触和机会**；Hero 决定的是**如何回应机会，以及承担什么后果**。

## 5. 不可混淆的状态

| 状态类别 | 例子 | 不应该做的事 |
|---|---|---|
| 世界事实 | 外来者确实到村、某处出现痕迹 | 因玩家没看见就删除事实 |
| 角色知识 | 蜜忒听到传闻；Hero 尚未获知 | 把线索簿同步给所有 NPC |
| 角色信念 | 医生怀疑是压力；居民误传为旧钟声 | 把猜测直接写成真相 |
| 关系 | 蜜忒担心 Hero；Hero 信任或不信任她 | 用一个好感值替代所有维度 |
| 行为/动机 | Hero 计划调查；医生选择回避 | 把计划视为已完成行动 |
| 机会状态 | 可以联系复国军；森林调查仍可继续 | 把机会开启直接等同于结局 |
| 结局条件 | 某条完整因果链最终满足 | 在 Lullaby 中提前硬编码 Hero 的最终结局 |

## 6. 重要剧情必须有可观察反馈

玩家应能从游戏中感知选择的影响，但不一定立即知道真实后果。反馈可以是：

- NPC 日程改变、临时缺席或主动来访；
- 对话措辞、回避行为或对同一事件的不同说法；
- 物件位置、痕迹、记录或某条信息的出现/缺席；
- Hero 后续是否提及某个消息、是否有新的调查方向；
- 错过主要现场后留下的次级证据或传闻。

避免用“世界线 +1”作为主要反馈。数值可在系统内部使用，但玩家感知应来自人物与世界的变化。

## 7. 设计护栏

- 不把示例自动升级为 canon；复国军消息如何影响接触机会、森林调查如何影响遗物获取，仍需跨项目设计。遵循 Hero 仓库当前故事基线：凡人之墓不发生身体结合；永恒乐园与烈火天罚均涉及身体结合，但走向与后果不同。
- 不要求每个日常动作都改变主线；世界线变化应有阈值、传播渠道和合理的累积过程。
- 关键事件可以错过，但重要事实原则上应留下代价更高、信息更少或风险更大的替代路径，除非明确设计为不可逆悲剧。
- 蜜忒的善意与纯真是真实的；系统可以让善意产生复杂后果，但不能暗示她早已知晓并操控一切。
- Hero 不知道蜜忒的真实身份，除非未来剧情通过明确、可验证的事件改变这一知识状态。
- 跨游戏同步采用稳定事件 ID 和语义合同，不共享内部实现细节。
- 任何结局判断都必须能追溯到玩家行动、角色知识、世界事实和已满足的条件。

## 8. 实施顺序

1. 为 Lullaby 建立角色记忆、知识来源和事件因果的基础数据模型。
2. 先让三名关键 NPC 的行为真正改变日程、对话、现场或可获得信息。
3. 为重要行动生成稳定的事件 ID 和可测试的状态变化。
4. 为 Hero 建立对应的输入/机会条件；两边分别测试，不在此阶段做运行时跨游戏依赖。
5. 设计少量端到端因果路径，验证玩家是否能看见影响、能否错过、错过后是否软锁。
6. 再扩展普通 NPC 和更多世界线分支。
