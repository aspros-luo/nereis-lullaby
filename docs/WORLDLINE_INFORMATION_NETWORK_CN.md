# 世界线信息传播模型（原型实现）

## 目标

信息必须经过人物、渠道和时间，而不是因为某个世界事实已经发生，就自动对所有角色可见。本系统为未来的跨区域事件提供可测试的基础设施，不代表商人、教会职员或复国军军需官已经加入当前游戏。

## 四个必须分开的层次

1. **世界事实**：由世界线事件台账记录，并关联事实首次出现的事件。
2. **角色知识**：角色亲历，或通过明确记录的渠道获得的信息。仅收到传闻不自动授予此项。
3. **收到的消息**：某个发送者通过特定渠道向某个接收者传递某个事实主张；消息可有延迟和可信度。
4. **角色信念**：接收者根据消息可信度形成的置信程度。它不是真相，也不会反向修改世界事实。

## 时间与投递

- 游戏每个时段对应一个离散 tick：`(day_index - 1) * 3 + slot_index`。
- 发送时记录 `sent_tick` 和 `arrival_tick = sent_tick + travel_slots`。
- 只有推进到达时段后，消息才进入收件箱。
- 同一消息 ID 只能发送一次；重复推进同一 tick 不会重复投递，时间不能倒退。
- 信念置信度采用保守的组合规则，单条消息不会直接把信念推到 1.0；这只是原型算法，后续可根据玩法验证调整。

## API 与存档

文件：`scripts/managers/worldline_information_network.gd`

- `publish_message(...)`：校验事实、来源事件、发送者与渠道后登记消息。
- `advance_to(tick)`：按时段投递到期消息。
- `get_inbox(character_id)`：读取接收者的消息副本。
- `get_belief_confidence(character_id, fact_id)`：读取置信度，不代表角色掌握客观事实。
- `to_save_data()` / `load_save_data(data)`：序列化消息、收件箱、信念与时间；拒绝重复 ID、损坏结构、无效置信度和不一致的投递记录。

主场景已经在推进时段时调用投递，并将网络状态纳入保存/读取。旧存档没有该字段时会恢复为空网络。

## 当前边界

- 该系统已经写入主循环和烟测代码，但**尚未由 Godot 实际运行**。
- 目前尚未把商人、教会小职员、复国军小军需官等跨区域人物接入原型，也没有为了演示而硬编码未经确认的剧情消息。
- 当前已将医生关于睡眠/日期的报告、照料者与礼拜主持者对习俗的说明接入零时延对话消息；消息抵达会写入世界线事件台账，但不会自动授予客观事实知识。
- 下一步应让跨区域人物之间的明确行动产生延迟消息，并在 UI 中呈现“谁告诉了谁、何时抵达、对方是否相信”，同时保留人物权限和知识边界。
