# 《蜜忒之歌》正式立项基线

> 状态：立项方向已确认。本文记录已批准的项目决策，不代表所有世界观和剧情细节已经定稿。
> 更新规则：重大变更必须同时更新中英文版本，并标注“已确认 / 提案 / 待讨论”。

## 1. 已确认的项目定位

- **类型与呈现**：日程模拟 + 自由探索 + 视觉小说。
- **时间结构**：每天分为早晨、白天、傍晚三个行动时段。
- **空间结构**：区域地图 + 地点探索；不是连续横版动作场景。
- **角色模拟**：关键 NPC 具有状态与日程，剧情事件和自主模拟混合驱动。
- **叙事视角**：以蜜忒视角为主，通过少量客观证据形成反差。
- **结局变量**：角色关系、调查/线索进度、世界状态分别计算，再共同影响结局。
- **开发顺序**：先验证核心系统原型，再制作垂直切片。

## 2. 蜜忒与玩家的信息差：核心叙事约束

蜜忒是生活在村庄里的少女。她对外神、仪式及其真实身份一无所知。她的纯真、善意、依恋和情感都是真实的，不是为了欺骗玩家而表演的伪装。

**本作不设置蜜忒主动使用的“灵视等级”或以调查超自然为目标的主角认知升级系统。** 玩家不是扮演一个知道自己在寻找外神真相的调查者。

叙事需要区分三层信息：

1. **蜜忒的体验与理解**：她看见、听见、记得、相信什么。
2. **玩家的推理**：玩家从环境、物品、对话、村民行动和前后矛盾中得出什么结论。
3. **世界的真实情况**：事件在客观层面如何发生，其中有些内容可以暂时不向蜜忒或玩家揭示。

三层信息可以不同，但必须遵守一致的因果规则。不要用无根据的旁白、任意篡改既有事实或角色突然失忆来强行制造反转。

## 3. 玩家如何调查，而不把蜜忒变成调查者

“调查”是玩家层面的玩法，不必是蜜忒明确意识到的任务。

- 玩家可以查看地点、物品和日常活动，阅读蜜忒对它们的自然理解。
- 线索簿记录玩家已见到的事件、说法、物件和矛盾；它是玩家的信息整理工具，不意味着蜜忒自动理解了隐藏真相。
- 游戏可以通过叙述措辞、场景细节、事件顺序、角色行为和重复出现的物件提供客观反差。
- 蜜忒的内心独白应符合她当时的知识、性格和情绪；不能突然用全知视角解释外神。
- 可以让玩家提出假设，但不要把未证实的假设自动写成客观事实。

## 4. 日常循环

每天有三个行动时段：

- **早晨**：开始当天生活，观察村庄近况，选择活动或地点。
- **白天**：拜访、帮助、采集、探索、参加活动或处理个人事务。
- **傍晚**：继续活动、回访角色、触发部分事件，并结算当天状态。

以上是时间框架，不是最终活动清单。具体行动成本、能否跳过时段、夜间事件是否作为独立阶段，仍需通过原型验证。避免把游戏变成必须逐日完成的机械打卡表。

关键 NPC 有各自的日程、关系和状态。事件系统与自主行为共同推动村庄变化。玩家不在场时也可以发生事件，但重要信息应有合理的替代发现路径，避免因错过一次行动永久软锁主线。

## 5. 空间、线索与世界变化

- 使用区域地图进入具体地点；地点可依据时段、事件阶段和角色状态变化。
- 第一版包含村庄核心区域和一片森林区域，作为玩法验证范围，不代表最终世界地图。
- 线索簿记录玩家接触到的证据；不显示“灵视值”，也不把灵视作为开启隐藏内容的通用钥匙。
- 世界异变由叙事事件、条件和世界状态共同控制；异变后应改变旧地点、对话、角色行为或物品含义。
- 玩家应能回访熟悉地点，并从新的上下文重新理解过去的细节。

## 6. 结局与状态模型

以下维度必须逻辑分离：

- **关系状态**：蜜忒与角色之间的信任、亲近、冲突或承诺。
- **线索/调查状态**：玩家实际接触、记录或关联的证据。
- **世界状态**：已发生的事件、村庄变化、势力行动及阶段性异变。

结局可以综合这些维度，但不能把单一好感度当成全部剧情的开关。身体亲密事件不默认作为主要结局的硬性门槛。各结局的具体内容和条件仍待讨论。

## 7. 第一版原型与垂直切片

开发顺序：

1. 建立最小可运行的项目与状态模型。
2. 验证早晨/白天/傍晚的行动循环。
3. 验证区域地图、地点访问和时段变化。
4. 验证关键 NPC 日程与事件混合驱动。
5. 验证线索簿如何记录玩家证据，而不改变蜜忒的知识边界。
6. 再制作垂直切片：一个小型村庄、三个行为有区别的关键村民、一片森林区域、线索簿，以及一次前后差异明显的世界异变。

以上规模是开发提案，不是最终内容上限。优先验证循环是否有趣，再扩展地图和剧本。

## 8. 状态标签与不可擅自定稿事项

### 已确认
本文件第 1、2、4、6 节所列项目方向与设计约束。

### 提案
三名关键村民、小型村庄加森林、一次关键异变的垂直切片；具体活动和技术实现。

### 待讨论
- 仪式的真实目的、机制和参与者各自知道多少。
- 仪式结构位于村庄、森林，还是多个地点共同构成。
- 村民为何以及在什么条件下保护蜜忒。
- 教会、古神、外神与王国历史素材的最终因果和时间线。
- Hero 的命运、复国军的作用、跨游戏事件的先后顺序。
- “凡人之墓”“永恒乐园”“烈火天罚”等结局的正式条件和内容。
- 村民成为邪教徒、百人群体等具体桥段是否采用。

任何提案都不能仅因写入设计文档就自动成为世界观定稿。

## 9. 项目边界与工作纪律

- 本仓库只开发《蜜忒之歌》的日程模拟、地点探索和视觉小说玩法；不把《Nereis-Hero》的动作 RPG 实现混入本仓库。
- 重要设计文档保持中英双语。
- 在 `development` 分支持续开发，完成阶段性检查后再提交里程碑。
- 不主动触发 GitHub Actions。
- 每个新对话先阅读 `docs/SESSION_START_HERE_CN.md` 与英文对应文件。
