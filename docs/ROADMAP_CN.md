## 阶段 3：双视角世界线与因果事件
- [x] 建立中英文双视角因果合同，区分世界事实、角色知识、行为意图、机会与结局条件。
- [x] 建立可追溯事件台账、显式知识授予、机会状态与存档序列化。
- [x] 为事件台账、信息传播和 NPC 行为补充自动化烟测代码（尚未由 Godot 实际运行）。

## 阶段 4：人物矩阵与自主行为
- [x] 建立三名关键 NPC 的行为卡：目标、动机、知识边界、记忆、关系维度和压力反应。
- [x] 建立跨区域人物的影响矩阵与候选因果网络（仅设计提案，尚未实现为玩法）。
- [ ] **进入条件：核心玩法阶段通过 Godot 引擎测试、存档回归与人工游玩验收。**
- [ ] 将多维关系、人物记忆、知识边界、消息触发和行为后果接入运行时。
- [ ] 让 NPC 行动能够产生可追踪的状态变化，而不只是显示文本。
- [ ] 验证至少数条“条件 → 决策 → 行动 → 结果 → 信息传播/错过”的因果链。

## 阶段 5：剧情与演出完善
- [ ] 核心玩法与人物矩阵通过验证后，再确定完整剧情、支线、结局和角色弧线。
- [ ] 扩大地图、村民数量、个人剧情、集体活动和异变阶段。
- [ ] 添加正式美术、音频、演出和更完整的文本呈现。
- [ ] 通过回归测试检查事件顺序、漏看线索和结局可达性。
- [ ] 所有尚未确认的结局名称和因果构想继续保持提案状态。

## 工程纪律
- 先验证核心玩法，再扩大人物矩阵，最后完善剧情。
- 核心验收清单：`docs/CORE_PLAYABILITY_ACCEPTANCE_CN.md` 与 `docs/CORE_PLAYABILITY_ACCEPTANCE_EN.md`。
- 不把原型剧情当作已定稿世界观。
- 不主动触发 GitHub Actions。
- 汇报时区分静态检查、自动化测试、引擎运行和人工游玩。
